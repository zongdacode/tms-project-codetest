# AI 能力规划

> 依据：《蓝图设计方案 V2.34》分析（[01-PRD分析报告.md](references/01-PRD分析报告.md)）+ 已确认约束"未来引入 AI 能力"。
> 状态：决策建议稿，随项目推进更新。

---

## 1. AI 能力地图（按 价值/落地难度 排序）

### P1 — 高价值、低风险（数据就绪后即可做）

| 能力 | 说明 | 依赖 |
|---|---|---|
| **邮件/附件 → 物流订单草稿** | PRD 明确订单来源含"客户邮件通知"。LLM 解析邮件及附件生成订单草稿，人工确认入库（human-in-the-loop） | 事件表、附件元数据规范 |
| **对话式查数（问数助手）** | "上周发杭州的运单哪些超时了？"——NL2SQL 或 API 级问答，走与用户相同的数据权限 | 结构化数据、权限透传 |
| **回单/单据 OCR 结构化** | 签收回单图片 → 结构化字段，回单审核从人工比对变抽检 | 对象存储 + 图片元数据 |
| **异常描述归类与处理建议** | 异常上报文本自动分类、划分责任方建议、历史相似案例 | 异常事件表 |

### P2 — 增值能力（有数据积累后）

| 能力 | 说明 | 依赖 |
|---|---|---|
| **ETA 预测与超时预警增强** | 基于历史线路/承运商/季节的实际时效预测到达时间，替代"当前时间+线路标准时效" | 节点事件时间线数据 |
| **运输方式/承运商推荐** | 按历史成本+时效+装载率推荐方案（PRD 项目目标里有"运输方案推荐"） | 计费与时效历史 |
| **计费/对账异常检测** | 对账前自动发现费用离点（运费偏离同类线路均值、重复计费） | 费用明细数据 |
| **智能配载增强** | PRD 已规划组托+装箱算法，可用求解器起步，积累数据后学习化增强 | 配载输入输出数据 |

### P3 — 远期

司机/客服对话机器人、对账差异自动解释、报价辅助。

### 决策

MVP **不实现任何 AI 功能**，但第 2 节的设计原则在 MVP 就必须落地——这是"未来引入 AI"的真正含义：不是留个按钮位，而是**数据从第一天就是结构化、事件化、可治理的**。

## 2. AI-Ready 设计原则（MVP 必须落地）

1. **节点事件表（Event Timeline）**：运单/订单的每个状态变化落一张统一事件表（对象、事件类型、时间、操作人、车辆位置等），而不是只存当前状态字段。这是 ETA 预测、时效报表、问数助手共同的数据底座，也顺便解决 PRD 中 6 个平行状态字段的设计缺陷。
2. **地址规范化**：客户/仓库地址统一带省市区编码 + 经纬度 + 电子围栏（PRD 已要求）；新增"地址标准化"约定（同一地址一个 ID），未来 AI 地址解析有挂靠点。
3. **附件元数据规范**：所有图片/PDF 入对象存储，业务表存元数据（类型=回单/送货单/过磅单、关联单据、上传人）。OCR/多模态处理只依赖元数据表。
4. **API-first + 模块边界**：模块间不裸查库，走服务接口——未来 AI 服务以"又一个调用方"的身份接入，不需要改核心代码。
5. **权限透传给 AI**：AI 问数/建议必须以当前用户身份过数据权限，禁止 AI 直连库绕过租户隔离。
6. **LLM 接入层抽象**：模型供应商可替换（自建网关或中间层），记录 prompt/版本/审计日志；涉及单据写入的场景一律人工确认。
