## 1. 三条执行纪律

1. **先文档后代码**：每块开工前把方案（表结构/接口/状态机/异常分支）补进对应文档章节并确认，实现严格按当次确认的文档走；文档与代码不一致按缺陷处理。
2. **红线进 CI**：架构红线（[10] R-1/R-2/R-5）用架构测试固化（工具已定 **ArchUnit 1.5.1**，[13] §3 已跑通），违规即构建失败，不靠人工自觉。
3. **小切片**：每块功能端到端交付（接口+测试+页面），单块规模控制在一次可评审的范围——保证 AI 协作生成的代码可被完整 review。

## 3. 批次 0：脚手架清单

### 3.1 工程骨架（模块树）

```
tms-project/
├── tms-common/          # 常量、统一响应 Result、异常码、UserContext、分页基类
├── tms-framework/       # 横切组件（见 3.2），自动装配 starter
├── tms-auth/            # 批次1实装；api/ 子包规范第一天就位
├── tms-base/            # 批次1实装
├── tms-plan/            # 计划表独立模块 [ADR-006]——批次2实装，壳先建
├── tms-core/            # 运输执行域：shipment/waybill/dispatch/track/sign/report 域优先分包
│                        #   [ADR-004][A7]；api/ 子包规范第一天就位
├── tms-admin/           # Spring Boot 启动模块 + application-{env}.yml
└── (wms/fee 不建——外部系统 [ADR-003/005])
```

- 工程规范沿用 [05-系统架构与项目结构方案](05-系统架构与项目结构方案.md)：模块间只依赖对方 `api/`（接口+DTO）、表前缀（sys_/base_/tms_）；主键**号段模式**（[ADR-016]，非雪花，[13] 已实测）。
- 依赖坐标与版本按 [13-gate0-技术栈验证报告](13-gate0-技术栈验证报告.md) §2 锁定矩阵；Boot 3→4 的坑见该文 §4（**照抄，否则第一步就编译不过**）。
- 其"补 4 模块"中的 integration/notify/rms：随外部系统归属与业务确认后再定（`[待定]`），骨架期不建。

### 3.3 红线测试与 CI

- 架构测试规则（随批次 0 落地）：
  1. tms-plan 与 tms-core 禁止互相依赖 Mapper/Entity（R-1）；
  2. 计划表实体字段白名单校验（R-2，新增字段必须改文档+测试同步改）；
  3. 跨模块只能 import 对方 `api/` 包（A-3 依赖纪律）。
- CI 流水线：编译 → 单测 → 架构测试 → 打包；落地为 `.github/workflows/ci.yml`（四步拆开，让红线失败独立可见）。**本机无 WSL2、Docker 引擎起不来**（[13] §5），原本设想的"docker compose 起本地依赖"不可用——批 0 的 CI 先只跑 H2 + 架构测试，MySQL/Redis 任务待环境解锁后补。
  注：`docker-compose.yml` 目前**尚未创建**，待真实库任务落地时一并补。
  注：`.gitignore` 与 `ci.yml` **只在本机做增量修改**，不要用 GitHub 网页端的
  "Add file → 选模板"——那个流程会整体覆盖，提交信息也看不出是替换。2026-10-05 发生过一次，
  详情见 [README](README.md) "维护注意"。
- 框架层常驻测试（从 [13] §3 提升，非一次性脚本）：号段发号唯一性、事务性发件箱同事务、回滚一致性、幂等消费去重、分页 SQL 改写。

## 4. 每块功能的标准节奏

```
① 方案确认    → 表结构/接口/状态机/异常分支 补进 05/06 对应章节，评审拍板（半天）
② 后端实现    → 按确认文档生成代码 + 单元/集成测试
③ 红线评审    → 架构测试自动检查 + 人工抽查跨模块调用与事实/命令语义
④ 前端实现    → 同批完成页面，连真数据联调
⑤ 验收归档    → 文档-实现一致性核对，更新 README 状态表 → 进下一块
```

每块开工 checklist：对应文档章节已补全？该块依赖的 `[待定]` 已清零？（见 §6）

## 7. 完成定义（DoD）

每块功能验收必须同时满足：

1. 后端：核心链路有自动化测试；架构测试绿；接口文档随代码生成（工具已定 **springdoc-openapi 3.1.1**，[13] §6-6）。
2. 前端：页面走真实后端数据，非 mock。
3. 文档：对应章节与实现一致（抽查核对）；README 状态表已更新。
4. 遗留：新增 `[待定]` 项已登记到对应文档待定清单。
