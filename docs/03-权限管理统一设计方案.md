# OTWB 统一权限管理设计方案（综合版）

| 文档属性 | 内容 |
|---|---|
| 文档版本 | V1.0（基于《OTWB权限管理方案规则》） |
| 编写日期 | 2026-10-02 |
| 适用范围 | OTWB 全端（CMP/MDM/OMS/TMS/WMS/BMS/RMS + 承运商端 + 司机/客户小程序） |
| 文档目的 | 解决"同一用户在多个账套下重复维护多套账号/角色/数据权限"问题，输出统一可实现的权限模型 |

## 1. 要解决的问题

旧系统（账套制 CMP）把用户、角色、数据权限全部挂在账套之下，导致：

| 场景 | 旧模式的维护成本 |
|---|---|
| 集团物流部 1 人管 3 个工厂 | 3 个账号 × 各自（角色 + 数据权限）≈ 9 次配置 |
| 承运商服务 5 个工厂 | 5 个租户各开户、各配权限；新接 1 个工厂 = 再来一轮 |
| 功能菜单/字段规则调整 | 每账套 × 每角色重复修改，遗漏即泄漏或不一致 |
| 跨单元接单（拼车池）、承运商统一视图 | 账套隔离墙直接堵死，需要额外开洞 |
| 权限盘点/审计 | 需逐账套核对，集团层面无单一事实 |

## 2. 核心结论（一句话）

**账号与账套彻底解耦。一个用户 = 一份身份 + 一份角色 + 一份数据范围。**

"能看哪些数据"不由"账号属于哪个账套"决定，而由三个互相独立的要素决定：

```
功能权限   = union(所挂功能角色) ∩ 用户二次收窄          —— 能做什么（菜单/按钮/字段）
数据范围   = 内部：归属推导默认 ∪ 显式附加范围对象，再 ∩ 二次收窄
             外部：合同线路授权（首选）∪ 当前承接参与方 ∪ 邀约/广播（自动推导，零配置）
参与方身份 = 承运商组织 / 客户组织 / 司机本人              —— 与我相关；改派即转移（见 §11）
```

账套（owner_tenant_id）只是**单据的属主属性 + 行级过滤字段**，不再是账号的归属容器。

## 3. 三层模型

```
┌─ 身份层 ──────────────────────────────────────────────┐
│ user（全集团唯一，一份账号一次登录）                     │
│   └ org_id 归属组织：控股 / 事业部 / 工厂 /            │
│      承运商组织 / 客户组织 / 司机（个人）               │
│   用途：① 推导默认数据范围  ② 管理委托边界             │
│   注意：归属组织 ≠ 数据隔离墙（隔离墙 = 行级过滤）      │
├─ 功能层 ──────────────────────────────────────────────┤
│ user ↔ 功能角色（多对多）                              │
│   角色 = 菜单/页面/按钮 + 字段三态，与数据范围无关      │
├─ 数据层 ──────────────────────────────────────────────┤
│ 内部用户：默认范围(归属推导) ∪ 显式范围对象 ∩ 收窄     │
│ 外部用户：参与方规则自动推导（承运商/客户/司机）        │
│ 例外形态：广播池豁免、拼车单关联属主可见                │
└──────────────────────────────────────────────────────┘
```

### 3.1 身份层：一人一号，全集团唯一

- 用户表全集团一套；归属组织（org_id）只表示"这个人/组织属于谁"，用于默认范围推导与管理委托，**不参与数据隔离**。
- 兼职、跨单元、集团条线人员：**不建第二个账号**，通过附加数据范围对象扩展（见 3.3）。
- 归属组织树：控股 → 事业部（=单元）→ 工厂（=账套=tenant）；承运商组织/客户组织为外部平行节点；司机挂个人身份。
- 外部用户（承运商/客户/司机）同样一人一号进入同一套身份体系，仅 user_type 不同。

### 3.2 功能层：角色只管"能做什么"（继承原方案）

- 功能角色承载菜单/页面/按钮勾选 + 字段三态（可见/掩码/隐藏），**不再承载数据范围** —— 这是消除重复维护的关键一刀：同一职能（如"调度员"）全集团只有一份角色配置，菜单变更改一处即全集团生效。
- 多角色取功能并集（菜单/按钮集合的并集是安全的，不存在数据泄漏问题）。
- 角色模板库：平台预置职能模板（订单客服/调度/仓管/园区/对账/审核/报表/承运商端/客户端/司机端…），新建角色从模板复制。
- 用户二次收窄（减法清单：摘菜单、字段收紧）、临时授权（有效期）、恢复角色默认：全部照原权限文档执行。
- 字段权限建议修订：由"按页面配置"改为**对象级默认 + 页面级例外**，新增页面默认继承，消除漏配泄漏。

### 3.3 数据层：两条规则路径 + 例外形态

#### A. 内部用户：默认推导 + 显式附加

**默认范围由归属组织自动推导，零配置：**

| 归属组织 | 默认数据范围 |
|---|---|
| 工厂 | 本账套 |
| 事业部 | 本事业部下全部账套（动态：新增工厂自动纳入） |
| 控股/平台 | **默认空**（安全兜底），需显式授权范围对象——内置「全集团」对象供平台角色使用；全量导出/资金类按钮另行管控 |

**跨范围需求 = 附加"数据范围对象"（可复用、命名、共享）：**

```
数据范围对象 data_scope：
  units[]                          —— 界面级联选择器（事业部）
  account_sets_mode: ALL_UNDER_UNITS | EXPLICIT
  account_sets[]                   —— EXPLICIT 时生效（落库主粒度=账套）
  carrier_filter:        无 | 全部 | 明细{carriers[], include_empty}
  eff_ship_park_filter:  无 | 全部 | 明细{parks[], include_empty}
  eff_dest_park_filter:  无 | 全部 | 明细{parks[], include_empty}
```

设计要点（与原权限文档的差异及理由）：

1. **账套是唯一的主授权粒度，多个范围对象的并集 = 账套清单的并集（真并集）**。原方案"多角色逐维并集 = 笛卡尔积"的越权组合漏洞在账套维度（隔离墙维度）上被天然消除；承运商/园区作为**可选的统一过滤器**对用户全部账套生效（扁平语义，简单可解释、可索引）。极少数"不同账套不同承运商"需求：拆分为两个用户，或在生效范围预览确认后接受扁平语义。
2. 落库以账套为单位、单元仅作级联选择器——避免"单元→账套→承运商"伪从属树（承运商是控股级共享主数据，并不归属账套）。
3. 「全部」动态语义保留：`ALL_UNDER_UNITS` 表示所选事业部下全部账套含未来新增，新增工厂零重配。
4. 「包含空值」保留，但**按岗位预置进角色模板**（OMS 客服/调度勾"承运商空值"——未匹配承运商的新订单是生命周期状态，不是脏数据）。
5. 多范围对象叠加时，界面必须展示**生效范围预览**（解析后的账套清单 × 过滤器）并二次确认。
6. 退货镜像匹配（eff_ship_park/eff_dest_park 写入时按镜像算好，见第 5 节）、「全选≠全部」、级联联动、取消空值收窄：照原文档执行。

#### B. 外部用户：参与方规则自动推导（零配置，这是承运商"零维护"的关键）

| 用户类型 | 行级过滤规则 | 跨工厂效果 |
|---|---|---|
| 承运商用户 | 当前承接：`carrier_org_id = 本组织`；未分配需求：线路 ∈ 本组织生效合同线路（招标授权推导） | 服务 N 个工厂 = 自动统一视图，**任何配置都不用做**；授权来源详见表 §11.2 |
| 客户用户 | `customer_org_id = 本组织` | 同上 |
| 司机 | `driver_id = 本人` | — |

- 外部用户**不配数据范围对象**；新工厂上线、新账套开通，承运商自动看到新工厂推给它的运单（参与方列匹配），维护成本为零。
- 改派即转移：承运商改派后，原承运商立即失去该单可见性（状态过滤而非历史快照），规则见 §11.2/§11.3。
- 功能权限用平台预置端侧角色模板；承运商管理员在**组织内**做挂角色/用户管理（见第 6 节委托）。

#### C. 例外数据形态（跨单元接单场景的专门规则）

| 形态 | 规则 |
|---|---|
| 临时议价池 / 拼车池 | **广播数据**：豁免属主与范围过滤，按状态对全部承运商可见；池内需求展示要素级信息，**各承运商报价互不可见**（参与方过滤） |
| 拼车运单 | 可见性 = 自身属主 ∈ 我的账套集合 **OR** 关联订单属主 ∈ 我的账套集合（双方货主都能看到这张拼车单及其跟踪/签收）。备选方案：确认后各货主各建一张运单共享车辆资源（同时满足对账按工厂分单）——**二选一，见第 9 节决策点** |
| 控股平台用户 | 默认全部，但"全量导出/跨板块资金操作"类按钮单独控权 + 强制导出审计 |

#### D. 操作上下文（解耦后的必要补充）

账号不再绑定账套后，**创建单据需要确定属主**：内部用户建单/导入时选择操作账套（owner_tenant_id），默认=归属工厂（归属为事业部/控股的用户必须显式选择），界面常驻上下文切换器，选择记录审计。承运商/司机/客户的操作对象都是已有单据，无需选择属主。

## 4. 统一查询拦截（服务端单点强制）

权限中心输出"数据过滤条件"，查询拦截器按用户类型注入——**一个拦截器，两条规则路径，一个豁免注册表**：

```sql
-- 内部用户
owner_tenant_id IN (生效账套集合)
  AND (carrier_filter 无 | carrier_org_id IN (...))
  AND (eff_ship_park_filter 无 | eff_ship_park IN (...))
  AND (eff_dest_park_filter 无 | eff_dest_park IN (...))

-- 外部用户：承运商 = 当前承接 ∪ 合同线路未分配需求（§11.2）
carrier_org_id = 本组织 OR (route_id ∈ 本组织生效合同线路 AND 状态 = 待分配)
customer_org_id = 本组织     /  driver_id = 本人

-- 豁免表：广播资源类型（议价池/拼车池）不注入属主与范围条件，仅状态过滤
```

性能与覆盖面要求：

1. 单据写入时**物化 `eff_ship_park` / `eff_dest_park`**（按退货镜像规则算好），拦截器全部为单列 IN 条件——避免原方案 `(NOT is_return AND ship_park IN ...) OR (is_return AND dest_park IN ...)` 双列 OR 导致的索引失效（运单大表 + "治慢查询"目标下不可接受）。
2. 复合索引第一版就位：`(owner_tenant_id, 运单日期)`、`(carrier_org_id, 运单日期)`、`(customer_org_id, 状态)`。
3. 所有读通道消费同一份权限解析：列表/详情/筛选/导出/统计/**报表预聚合汇总表（按五维聚合键过滤）/搜索（ES query 层同规则）/AI 问数（以用户身份透传）**。通道清单纳入权限中心的覆盖面测试。
4. 仓库→园区归属变更、`is_return` 映射变更：权限相关主数据变更纳入审计；策略默认"变更影响新单据，历史单据按快照列不变"（需要追溯重算时显式发起）。
5. 导出行为审计（谁、何时、什么范围、行数）+ 掩码字段禁排序/合计/分组统计命中，打印模板走同一字段权限。

## 6. 管理委托（权限管理员的权限）

权限管理动作本身是功能权限对象，其可管理范围按**归属组织树**继承：

| 管理员 | 可管范围 |
|---|---|
| 控股平台管理员 | 全部：角色模板、范围对象、跨单元授权 |
| 事业部管理员 | 本单元内：用户、功能角色复制与微调、范围对象（仅引用本单元账套）、二次收窄 |
| 工厂管理员 | 本工厂用户挂角色 + 收窄 |
| 承运商管理员 | 本组织用户挂端侧模板角色（不能自建数据规则——数据范围是参与方自动推导的，无可配项） |

越界保护：委托管理员的候选范围以自身归属组织为上限，服务端校验，全量审计保留 ≥ 2 年。

## 7. 维护成本对照（本方案的核心收益）

| 操作 | 旧模式（账套制） | 本方案 |
|---|---|---|
| 新员工入职（单工厂） | 建账号 + 配角色 + 配数据权限 | 建账号（选归属）+ 挂功能角色，≤1 分钟 |
| 新员工入职（跨 3 工厂） | 3 账号 × 全套 ≈ 9 次配置 | 1 账号 + 挂角色 + 附加 1 个范围对象 |
| 用户新增负责 1 个工厂 | 新账号 + 全套配置 | 范围对象加 1 个账套（或归属推导自动覆盖） |
| 功能菜单/字段规则调整 | 每账套 × 每角色重复改 | 改 1 处（角色/模板），全集团生效 |
| 新工厂上线 | 相关用户逐租户重配 + 承运商逐租户开户 | 内部：ALL 模式自动纳入 / 范围对象加账套；**承运商：零配置** |
| 承运商新接 1 个工厂业务 | 工厂租户开户 + 配权限 | 0（参与方自动可见） |
| 权限盘点/审计 | 逐账套核对 | 单一事实：用户 → 角色 + 范围 + 收窄，一张清单 |

## 8. 相对原权限文档的继承与修订清单

**全部继承**：角色基座、二次收窄（只收窄不越界 + 越界自动同步 + 恢复默认）、字段三态与掩码服务端执行、五维维度与级联界面、「全部」动态全量、「包含空值」、退货镜像匹配、临时授权、即时生效（缓存 ≤ 1 分钟）、服务端查询拦截单点强制。

**修订**：
1. 数据范围从角色中剥离 → 可复用"范围对象" + 归属推导默认（消除多账套/多职能重复维护的根源）；
2. 多范围叠加语义显式化：账套维度真并集，过滤器扁平统一 + 生效预览确认；
3. 字段权限改"对象级默认 + 页面级例外"；
4. 新增外部用户参与方规则路径（原文档完全未覆盖，而承运商端在 MVP 范围内）；
5. 新增广播豁免、拼车单关联属主可见、竞价互盲；
6. 空值语义重新定义为生命周期状态，岗位模板预置；
7. eff 园区快照列落库（性能 + 主数据变更不追溯）；
8. 新增管理委托章节、导出审计、读通道覆盖面清单；
9. 新增订单分配与承运商授权管控（§11）：招标线路授权推导、询价报价互盲、平台改派与原承运商可见性收回。

## 9. 需业务拍板的决策点

| # | 决策点 | 建议 |
|---|---|---|
| 1 | 拼车运单可见性：关联属主规则（推荐，实时性好） vs 确认后拆单（对账干净） | 关联属主规则 + 对账仍按工厂拆分 |
| 2 | "不同账套不同承运商过滤器"的极少数场景：拆用户 vs 接受扁平语义 | 拆用户；界面预览兜底 |
| 3 | 部门/客户维度是否纳入范围对象（账套内再细分） | 一期不做（保持简单），范围对象表结构预留扩展列，出现真实需求再启用 |

## 10. 验收标准（增量）

| # | 用例 | 预期 |
|---|---|---|
| 1 | 集团用户（归属事业部）挂 1 个功能角色 | 单账号看到本事业部全部工厂单据，无第二账号 |
| 2 | 用户附加范围对象（跨事业部 2 个工厂） | 生效范围预览确认后，三厂单据并集可见 |
| 3 | 承运商账号，服务 5 个工厂 | 零数据配置，5 厂运单统一列表可见 |
| 4 | 新工厂上线（角色用 ALL 模式 / 承运商） | 内部 ALL 模式用户与承运商自动可见，零配置变更 |
| 5 | 功能角色菜单调整 | 该角色全部用户（跨工厂）即时生效，仅一处修改 |
| 6 | 拼车运单（双方货主确认，A 方建单） | B 方用户可见该运单及跟踪/签收；对账单仍按工厂分单 |
| 7 | 议价池 | 跨单元承运商均可见池内需求；承运商间报价互不可见 |
| 8 | 未匹配承运商的新订单（OMS 客服角色） | 模板预置空值可见，客服可正常处理 |
| 9 | 外部用户调用非本组织单据接口 | 403，审计留痕 |
| 10 | 事业部管理员尝试为本单元外账套配置范围对象 | 拒绝并提示 |
| 11 | 全量导出（控股角色） | 导出成功且审计记录（人/时间/范围/行数） |
| 12 | 掩码金额列排序/合计 | 服务端忽略或拒绝，无信息泄漏 |
| 13 | 承运商合同线路生效 / 到期 | 生效：该线路未分配需求进入接单大厅；到期/终止：新需求不再出现，已承接单据仍可见 |
| 14 | 平台改派承运商 A→B | B 即时可见；A 立即失去该单全部可见性（含历史明细）；A 名下已发生费用/对账单仍可见 |

## 11. 订单分配与承运商授权管控（询价/插单/拼单）

### 11.1 分单决策流（按线路合同状态自动路由）

```
物流订单确认
 ├─ 线路有生效合同 →【合同直派】自动匹配合同承运商 + 合同价格体系计费 → 生成运单
 │    └─ 承运商拒单（运力不足）或调度员主动 →【二次询价】（留痕）
 │         → 建询价单：定向邀约 N 家 +/或 挂入询价池 → 承运商报价（互盲）→ 定标
 │            ├─ 成交价 ≤ 合同价 → 直接生效，差额进降本统计
 │            └─ 成交价 > 合同价/超阈值 → 审批通过后才绑定
 └─ 无合同 →【临时插单】定向议价（一单一议，录价+事由留痕）或 在线竞价（广播池）→ 定标建单
      └─ 线路月发运量达阈值 → 系统提示补签合同/招标（租户配置）
同线路+同时效存在多方货主需求 →【拼单池】撮合 → 双方确认 → 合并运单照走上述选商逻辑
```

### 11.2 承运商数据授权：由业务记录自动推导，零手工配置

**首选授权方式 = 招标/合同线路**：

| 授权来源 | 可见内容 | 生效与收回（全自动，无权限配置项） |
|---|---|---|
| ① 招标/合同线路（**首选授权**） | 本组织**生效合同线路**上的未分配需求（接单大厅、线路需求明细） | 合同/招标生效=授权；到期/终止/改签=自动收回 |
| ② 当前承接（参与方） | 已分配给本组织的运单/任务单/节点跟踪/回单 | **改派即转移：改派后原承运商立即不可再查看**（状态过滤而非历史快照）；正常完成的单据参与方不变，永久可见 |
| ③ 询价邀约 | 被邀约的询价单及需求要素 | 邀约即见；定标/撤回后收回 |
| ④ 广播池 | 询价池/竞价池/拼单池需求（豁免属主过滤） | 按状态可见；定标后从池消失 |

**结算例外**：被改派的原承运商，其名下**已发生的费用明细与对账单仍可见**（结算凭证，参与方不变），但运单执行明细不可见。

### 11.3 平台级调度改派

- 按钮「改派承运商」按角色授予：工厂调度角色（数据范围天然限定其本厂单据）；**平台运力管理角色可跨厂改派（平台级调度修改）**，数据范围决定可改派的单据范围。
- 改派必填事由，全量审计；保存即时生效（缓存 ≤ 1 分钟），新承运商按参与方规则自动获得全部可见性。
- 联动：在途改派触发转车流程（转车码）；已发生费用按原承运商保留结算；改派历史入事件时间线（货主双方可见，原承运商不可见）。

### 11.4 询价/报价与定标管控

| 管控点 | 规则 |
|---|---|
| 发起/定标分离 | 「发起询价」与「定标」为两个按钮，可授不同角色（调度员发起、调度主管定标，四眼原则） |
| 报价互盲 | 报价单按参与方过滤（`carrier_org_id = 本组织`），服务端强制，无配置项 |
| 价格偏差 | 成交价 > 合同价 X% → 审批（X 按工厂在租户配置表配置） |
| 定标约束 | 最少报价家数、非最低价必填理由、无合同线路发运量阈值提示 → 租户配置表 |
| 全程留痕 | 询价事由（枚举）、邀请名单、全部报价、定标理由，保留 ≥ 2 年 |

### 11.5 数据模型增量

```sql
rfq(id, owner_tenant_id, route_id, invited_carriers[], status, reason)   -- 询价单
quote(id, rfq_id, carrier_org_id, price)                                -- 报价单（参与方互盲）
-- 承运商线路授权不建独立授权表：由合同/招标生效记录直接推导（生效=授权，终止=收回）
```
