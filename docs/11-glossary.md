## 术语表

| 术语 | 英文/代号 | 定义 | 出处 |
|---|---|---|---|
| 业务单号 | biz_order_no | 全局唯一、不可变的业务单据编号，由源头系统生成；跨系统追溯主键 | [ADR-012] [05]§4 |
| 行号 | line_no | 业务单据内的行序号，与业务单号组成跨系统关联键 | [ADR-012] |
| 计划表 | tms_order_plan | TMS 内独立的单据订单/计划协调表，只记录主单四节点状态；订单中心雏形 | [ADR-006/007] [05]§2 |
| 订单中心 | Order Center | 未来由计划表迁出形成的独立主单协调系统 | [ADR-015] [09] |
| 出库单 | Outbound Order | 发货仓 WMS 的出库作业单据 | [02] |
| 入库单 | Inbound Order | 目的仓 WMS 自主创建的收货单据 | [ADR-008] [04] |
| 发运单 | Shipment Order | TMS 依据出库单创建的运输执行单据 | [04] 流程2 |
| 运单 | Waybill | TMS 运输执行单据 | [02] |
| 签收 | Signed / POD | TMS 侧收货方签收确认动作，与 WMS 收货是两个独立动作 | [ADR-008] |
| 事件语义接口 | Event-semantic API | 以"已发生事实"为契约的接口，当前经 HTTP 同步调用，视为事件传输层 | [ADR-010] [06] |
| 事实 / 命令 | Fact / Command | 事实=已发生、不可拒绝；命令=请求执行、可被拒绝 | [06]§2 |
| 本地事件表 | Outbox / Inbox | 发送方落库待投递记录（outbox）与接收方幂等消费记录（inbox） | [05]§3 [ADR-011] |
| 幂等键 | Idempotency Key | 防重复处理的唯一约束：事件 ID+业务单号+行号+状态类型 | [05]§5 |
| 冲销 | Reversal | 对已发生事实的抵消标记，独立状态迁移，不回退原状态 | [ADR-013] [05]§2 |
| 履约跟踪视图 | Fulfillment View | 只读聚合主单与运输执行状态的查询视图，服务客服，不承载业务 | [03]§5 |
| 粗粒度单体 | Coarse-grained Monolith | 按领域整体部署的单体系统，内部模块化 | [ADR-001] |
| ADR | Architecture Decision Record | 架构决策记录，变更只增不删 | [01] |
| 最终一致 | Eventual Consistency | 跨系统数据允许延迟收敛，靠幂等+重试保证正确 | [00]§6 |
| 回退重试 | Backoff Retry | 按递增间隔重试失败投递，参数 `[待定]` | [06]§8 |
