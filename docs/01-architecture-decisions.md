- 编号连续引用，正文文档中以 `[ADR-xxx]` 标注依据。

<a id="adr-001"></a>
## ADR-001 三大领域独立单体部署与演进

- **状态**：`[已决策]`
- **背景**：团队规模、业务复杂度、运维能力不足以支撑完整订单中心与细粒度微服务；仓储/运输/结算职责边界天然清晰。
- **决策**：WMS、TMS、结算各自作为独立单体部署、独立数据库、独立发布节奏；系统间只通过网络接口与数据交换集成。**本项目仅建设 TMS**（WMS/结算归属见 ADR-003）。
- **影响**：+部署故障隔离、发布互不影响、各系统按自身变更频率投入设计；-跨系统事务消失，一致性依赖幂等+重试（见 ADR-011）。
- **被否决**：单一应用内三模块起步再拆（拆分成本后置但初期边界易腐化）；完整微服务化（运维能力不匹配）。

<a id="adr-002"></a>
## ADR-002 不建统一订单中心

- **状态**：`[已决策]`，触发重评估条件见 ADR-015
- **背景**：订单中心需要独立团队、高可用保障与全局数据治理能力，当前均不具备。
- **决策**：订单相关处理在各系统内独立完成；TMS 内设计划表承载主单节点协调（见 ADR-006/007）。
- **影响**：+以最低成本获得"类订单中心"协调能力；-协调逻辑寄居在 TMS，须靠红线防止 TMS 变成隐性订单中心（[10] R-8）。
- **被否决**：外采订单中台（集成与治理成本）；现在就建订单中心（人力不具备）。

<a id="adr-003"></a>
## ADR-003 WMS 为外部系统，仅约定集成边界

- **状态**：`[已决策]`（本项目不建设 WMS）
- **决策**：TMS 不建设 WMS。WMS 内部架构（模块划分、库存模型、仓型组织）由 WMS 建设方自行决定；本项目只约定集成契约（出库单同步、完成类事件，[06]）与集成纪律（不阻塞 WMS 主流程，[ADR-014]）。结算等其他外部系统的对接要求 `[待定]`，确定后另立 ADR。生态级参考建议（粗粒度单体、不按原材料/成品/线边仓拆微服务）传递给建设方，不构成本项目约束。
- **影响**：TMS 范围收敛；WMS 内部演进不纳入本套文档管理。

<a id="adr-004"></a>
## ADR-004 TMS 内部模块划分

- **状态**：`[已决策]`
- **决策**：TMS 内部按 **运单、调度、轨迹、签收** 组织模块，另设**计划表**为独立模块（不属于运输执行业务表，见 ADR-006）。计费功能已移出范围（ADR-017）。
- **影响**：运输执行域保持纯粹；计划表模块可整体迁出（ADR-015）。

<a id="adr-005"></a>
## ADR-005 结算集成（已废弃）

- **状态**：**已废弃**（2026-10-04）——结算/对账集成内容整体移除；外部系统归属并入 [ADR-003]。TMS 与结算等系统的数据供给要求待未来另行决策（届时新增 ADR）。

<a id="adr-006"></a>
## ADR-006 计划表独立于运单表，只通过接口交互

- **状态**：`[已决策]`（红线 [10] R-1）
- **背景**：计划表承担跨系统协调，若与运单业务表耦合，迁出订单中心时无法剥离。
- **决策**：计划表不侵入 TMS 运单相关业务表；两者只通过 TMS 内部接口交互；**禁止跨表 join、禁止计划表直接 update 运单表**（反之亦然）。
- **影响**：+未来迁移=搬表+换接口；-同一事务内的联动需接口化，多一次内部调用开销。

<a id="adr-007"></a>
## ADR-007 计划表只监控四个关键节点

- **状态**：`[已决策]`（红线 [10] R-2）
- **决策**：计划表只记录 **下发、出库完成、入库完成、签收完成** 四节点状态与时间戳 + 事件 ID + 版本号；不细化管理仓内拣货、上架、盘点等作业状态。
- **影响**：+计划表体量与逻辑恒小，可预测地迁出；-仓内进度查询回 WMS，不允许往计划表加列"顺手"解决。

<a id="adr-008"></a>
## ADR-008 收发货两侧动作分离

- **状态**：`[已决策]`
- **决策**：① 发货仓 WMS 出库单可同步给 TMS 创建发运单（发货侧由 TMS 承接运输执行）；② 目的仓收货由**目的仓 WMS 创建入库单并执行收货**；③ **TMS 签收与 WMS 收货是两个独立动作，允许存在差异**（司机拿到签收 ≠ 仓库点收完成），差异在履约视图中呈现，不强行合并成一个状态。
- **影响**：+符合现场实际（签收人≠仓管员）；-差异容忍规则 `[待补全]`（见 [04] 流程5）。

<a id="adr-009"></a>
## ADR-009 结算取数通道（已撤销）

- **状态**：**已撤销**（2026-10-04）——随结算集成内容移除。对外数据访问一律遵循 [ADR-010/011]（事件语义 + 可靠性机制）；外部系统禁读 TMS 业务库的红线保留在 [10] R-3。

<a id="adr-010"></a>
## ADR-010 同步接口按事件语义设计

- **状态**：`[已决策]` + `[未来演进]`
- **决策**：当前阶段优先同步接口，但契约按事件语义建模（"出库完成""签收完成""订单取消"），查询类走同步 API。**即使传输层是 HTTP，也应视为"事件传输层"而非点对点命令**——被调方记录事实、返回受理结果，不反向驱动主调方流程。
- **影响**：+未来切 MQ/事件总线时仅换传输适配层，语义与幂等模型不变；-要抵制"顺手设计成命令式接口（如"请你取消运单"）"的诱惑，命令与事实的区分见 [06]。

<a id="adr-011"></a>
## ADR-011 事实传递必须配套可靠性机制

- **状态**：`[已决策]`（红线 [10] R-5）
- **决策**：凡用同步接口传递业务事实，必须同时具备：发送方**本地事件表**、接收方**幂等消费**、**失败重试**；跨系统数据比对兜底机制 `[待定]`。前三者缺一，该集成不允许上线。
- **影响**：集成开发工作量增加约一档，换来故障可解释、数据可修复。

<a id="adr-012"></a>
## ADR-012 全局业务单号与跨系统关联键

- **状态**：`[已决策]`
- **决策**：全局业务单号统一生成规则（编码结构 `[待定]`，见 [05] 单号规范）；**跨系统关联键 = 业务单号 + 行号**；WMS、TMS、结算所有相关表必须存储该关联键。
- **影响**：+全链路追溯有稳定主键；-单号规则变更是跨系统破坏性变更，须 ADR 级评审。
- **补充（2026-10-04）**：单号由 **TMS 统一生成**（结构 `TMS-{类型码}-{YYYYMMDD}-{序列}`，前缀+类型+日期+序列）；上游源单号以独立字段 `source_doc_no` 保存、**不覆盖**单号；接口幂等去重键 = `source_doc_no + 行号`。

<a id="adr-013"></a>
## ADR-013 状态只前进，取消/冲销独立迁移

- **状态**：`[已决策]`
- **决策**：计划表节点状态只允许前进（下发→出库完成→入库完成→签收完成）；取消与冲销作为**独立状态迁移**处理（新增取消/冲销标记与时间戳），不允许把已完成节点"退回去"。
- **影响**：+状态机简单、历史不可变、审计友好；-逆向业务表达依赖独立事实（如退货单=新业务单号），见 [04] 流程 8。

<a id="adr-014"></a>
## ADR-014 WMS 主流程不被下游阻塞

- **状态**：`[已决策]`（红线 [10] R-4）
- **决策**：WMS 出库主流程不得被 TMS 等外部系统阻塞。TMS 接口失败时，WMS 出库照常完成；集成数据通过重试与补偿最终对齐。
- **影响**：+仓内作业（变更最频繁、可用性要求最高）不被外部系统拖累；-发运单创建延迟需在履约视图显性化，避免业务误判。

<a id="adr-015"></a>
## ADR-015 计划表可整体迁出为订单中心

- **状态**：方向 `[已决策]`，实施 `[未来演进]`
- **决策**：计划表即订单中心雏形。未来迁出时：计划表迁出、TMS 运单表**结构与业务逻辑不动**，只改造计划表与运单表之间的接口调用方式（进程内→远程）；WMS 等外部系统更新状态的对象从"TMS 计划表"切换为"订单中心"。
- **前置纪律**（现在就执行）：ADR-006/007 的隔离与不膨胀；关联键只用业务单号+行号（ADR-012）；接口契约不暴露 TMS 内部模型。

<a id="adr-017"></a>
## ADR-017 计费功能移出 TMS 范围

- **状态**：`[已决策 2026-10-04]`
- **决策**：运费计费相关功能**不在本期建设范围，后续单独规划**。原批次 6（运费）取消；tms-core（运输执行域模块，2026-10-05 前名为 tms-tms）不含 billing 子域；计划表四节点与履约视图不受影响。
- **影响**：签收完成后无自动计费环节；未来规划计费时需评估运单数据就绪度（是否预留费用要素字段届时定）。
